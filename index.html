Clinical exam · cDMFT (reference standard)

WHO 2013 examination, crown codes 0–9 for all 32 positions. The primary index cDMFT uses 28 teeth (no third molars), following the pDMFT convention; third molars are used only for cDMFT32. Lock the exam before photography.

WHO 2013 codes and scoring rules

D = codes 1, 2 · F = code 3 · M = code 4 (under 30 years; from 30 years code 5 is added). Codes 6, 7, 8, 9 are not counted in DMFT. U flag: reason for tooth loss unknown (record code 5 with U; sensitivity analysis recodes U as 4).

Intraoral photographs · 5 views

The photographer is not the examiner. Rate each view on 4 criteria (0 unusable · 1 usable with limitations · 2 good). A view meets the minimum when no criterion is 0; at most 2 retakes per view. Do not use AI output to decide on retakes.

AI diagnosis · pDMFT-AI

Record the output of pDMFT-AI run on the final photo set with the locked model version. This page does not run the model: paste or load a per-tooth result file, or enter it by hand. pDMFT coding: absent teeth merge WHO 4, 5, 8 into code 4.

Load results

Photo-based diagnosis · vDMFT

Two dentists read the same photo set independently, blind to the exam and AI results. Teeth coded differently by the two readers are settled by an adjudicator; vDMFT is the consensus result.

Comparison

Three measurements on the same person: cDMFT (clinical), vDMFT (dentists reading photos), pDMFT (AI). Opens only when all three are locked.

How to use

Each participant is one record. A record goes through 6 steps in the order set by the protocol; each step is done by a different person and locked when finished. This page walks through one new record from start to end.

Before you start

  • Share the page. The page is private. The owner (the PhD student) clicks Share and invites the examiner, photographer, the 2 reading dentists, the adjudicator and the AI engineer with permission to enter data. Everyone sees the same list of records.
  • Top right corner. Synced means records are shared and visible on every device. This device only means data lives only in this browser: go to Records → Backup before closing the page.
  • Save and Lock are different. Save keeps what you have entered; you can keep editing. Lock finalises that step; after locking it cannot be edited unless someone clicks Unlock and gives a reason (the reason goes into the audit log and the Excel export).
  • Blinding (on by default) hides the other methods' results during data entry: reader 1 cannot see reader 2's reading, and Comparison opens only when all three measurements are locked. Do not switch it off during real data collection.
  • The 6-step bar at the top shows the progress of the open record: a grey number is not started, amber is in progress, ✓ green is locked. Click a step to go to it.
1

ID · screening Coordinator

  1. Click + New record (top of the page). Step 1 opens with a blank record.
  2. Choose the Site (S1, S2, S3). The sequence number fills in with the next free number for that site; you can edit it or click Next number. The ID appears, e.g. S1-0001. If the ID already exists, the page shows it in red.
  3. Enter the exam date, age (completed years from date of birth), sex, group, examiner ID, photographer ID and device ID. Do not enter names: the record carries only the ID.
  4. Tick the 4 inclusion criteria and any exclusion criteria. The page shows Eligible or Not eligible. Ineligible people are still saved so they can be counted in the STARD flow diagram, but go no further.
  5. Click Save. The record now appears in Records.

Done when: the ID exists, the page says “Eligible”, and the record is saved.

2

Clinical exam · cDMFT Calibrated examiner

  1. Open the record (Records → Open) and go to Clinical exam.
  2. Choose the entry mode at the top of the chart: Surfaces (default, as in the original VOSER) or Whole tooth.
  3. By surface: click a tooth; below it a diagram of its 5 surfaces appears (4 for anterior teeth): O occlusal in the centre, B buccal, L lingual, M mesial (towards the midline), D distal. Type the code for the selected surface: 0 sound, 1 decayed, 2 filled with decay, 3 filled without decay, 6 fissure sealant. The selection moves to the next surface, then to the next tooth. For a missing, unerupted, prosthetic or unexaminable tooth type a whole-tooth code: 4, 5, 7, 8, 9. The tooth code is derived in WHO order: decay and filling → 2; decay → 1; filling → 3; sealant → 6; otherwise 0. Each tooth shows a small cross coloured by surface.
  4. By whole tooth: click a tooth and type 0–9; the selection moves to the next tooth (18 → 11, 21 → 28, then 48 → 41, 31 → 38). Faster, but DMFS and lesion-location analysis are not possible.
  5. Many sound teeth: code the affected teeth first, then click Uncoded surfaces = 0 (or Uncoded teeth = 0 in whole-tooth mode). Unerupted third molars: Uncoded third molars = 8.
  6. Tooth lost for a reason the participant cannot remember: code 5 (with code 5 the selection stays on that tooth), then click U flag or press U. A small U appears in the corner of the tooth; press again to remove it.
  7. Check the boxes computed below the chart: D, M, F, cDMFT (28 teeth), cDMFT32 (when all 4 third molars are coded), hDMFT, and with surface entry cDMF-S and hDMF-S (a missing tooth counts 5 surfaces posterior, 4 anterior).
  8. Click Save, then Lock clinical exam. Lock before the participant goes to photography.

Done when: all 28 main teeth are coded and the exam is locked. If more than 8 teeth are absent, the page warns that this is an exclusion criterion.

3

Photos · 5 views Photographer (not the examiner)

  1. Go to Photos. Click the frame of each view (Frontal, Right lateral, Left lateral, Upper occlusal, Lower occlusal) to choose a photo, or drag the photo onto the frame. Photos keep their original resolution.
  2. Rate the 4 criteria for each view (0 unusable, 1 usable with limitations, 2 good). A view with any criterion at 0 is Below minimum: retake, choose the new photo, increase Retakes and record the reason (blur, glare, saliva…).
  3. At most 2 retakes per view. If a view still fails after 2 retakes, the set is recorded as no output; the person stays in the denominator.
  4. Do not look at AI results when deciding on retakes.
  5. Edit photo (button under each photo): rotate 90°, flip horizontally or vertically (occlusal photos taken with a mirror are reversed), straighten (±20°), crop (click Crop then drag on the photo), brightness, contrast, saturation, colour temperature. Click Apply. The original is not changed; edits are stored as settings, marked “Edited”, and written to Excel. The AI and Photo reading steps have a View original button for comparison.
  6. Define in the SOP in advance which edits are allowed. Suggestion: only fix orientation (rotate, flip) and crop away areas outside the mouth; limit brightness and colour changes, because they can reveal or hide lesions. Readers and the AI must use the same version of each photo.
  7. Click Save (photos are uploaded now), then Lock final photo set.

Done when: 5 photos, all 5 views meet the minimum (or no output is recorded), and the set is locked.

4

AI diagnosis · pDMFT AI engineer

  1. Run pDMFT-AI (the locked version) on the final photo set outside this page. This page does not run the model.
  2. Go to AI diagnosis. Paste the results into Load results and click Apply, or click Load .json/.csv file. Format: one line per tooth tooth,code (e.g. 16,1), or JSON {"16":"1","26":"3"}. Invalid codes and third molars are skipped and reported.
  3. You can also enter or correct codes by hand on the tooth chart. pDMFT codes: 0 sound, 1 decayed, 2 filled with decay, 3 filled without decay, 4 absent, 7 fixed prosthesis, 9 not assessable.
  4. Record the model version, output hash and run time. If the model failed, tick AI produced no output.
  5. Click Save, then Lock AI output.

Done when: all 28 teeth are coded (or no output is recorded) and the output is locked.

5

Photo reading · vDMFT Reader 1, reader 2, adjudicator

  1. Go to Photo reading, choose the right role: Reader 1 or Reader 2, and enter the reader ID.
  2. View the photos on the left: click a view name to switch, click the photo to zoom. Code the 28 teeth on the right, choosing a mode at the top of the chart:
    • Surfaces (default): as in the clinical exam, each tooth has a diagram of surfaces O, B, L, M, D. Surface codes: 0 sound, 1 decayed, 2 filled with decay, 3 filled without decay, 9 not visible in the photo (common for mesial and distal surfaces of posterior teeth). Whole-tooth codes: 4 absent, 7 fixed prosthesis. The tooth code is derived: decay and filling → 2, decay → 1, filling → 3, all surfaces 9 → 9, otherwise 0.
    • Whole tooth: one code per tooth, exactly like the pDMFT-AI output.
    Do not guess: code 9 for a surface or tooth you cannot see clearly. Surface coding shows which surface the reader saw the lesion on, for comparison with the clinical location.
  3. Each reader clicks Save then Lock reading. Do not open the other reader's reading.
  4. When both have locked, the Adjudicator chooses the Adjudicator role. The adjudicator decides by whole-tooth code: only teeth the two readers coded differently (red outline) can be clicked; the table below shows both codes and the surfaces each reader recorded.
  5. Resolve all disagreements, click Save, then Lock consensus vDMFT. Agreement between the 2 readers (%, kappa) is shown in the blue box.

Done when: both readings and the consensus are locked.

6

Comparison PhD student, statistician

  1. When all three (clinical, consensus photo reading, AI) are locked, Comparison opens automatically. Before that, the page shows a lock and lists what is still pending.
  2. The three cards at the top: cDMFT, vDMFT and pDMFT with D, M, F. The boxes below: V − C, A − C, |A − C| − |V − C| (H3), hDMFT, tooth-level agreement and kappa.
  3. Tooth-by-tooth comparison: each column is a tooth, the three rows are clinical, photo reading and AI. A red outline marks a tooth that differs from the clinical exam. Clinical codes 4, 5, 8 all count as “absent”, because photos cannot show why a tooth is missing.
  4. Teeth decayed at the clinical exam, by surface: for each decayed tooth, the decayed surfaces, the location, what each reader recorded, and whether photo reading and AI detected it.
  5. Whole sample pools every fully locked record: monitoring of H1, H2 (equivalence ±0.5 teeth), H3 (non-inferiority, margin 0.25), sensitivity and specificity for decayed teeth, sensitivity by lesion location, and the Bland–Altman plot. This is a monitoring table; the main conclusions follow the analysis plan.

Records, export and backup

  • Records (button at the end of the step bar) lists every record with 6 progress dots. Click Open to continue a record, Delete to delete it permanently (with confirmation).
  • Export Excel: sheet Theo_nguoi (one row per person: indices, differences, photo quality, photo edits, lock times, unlock log), sheet Theo_rang (one row per tooth: clinical with surfaces, reader 1, reader 2, adjudicator, AI), sheet Tu_dien (dictionary). Column names are the same in both language versions.
  • Download photos .zip: file names follow the SOP, e.g. S1-0001_F_1_D2.jpg (ID_view_attempt_device); edited copies are in the da_chinh folder.
  • Backup to a .json file including photos; Open backup loads it into this page or another copy (the Vietnamese and English versions read the same backup file).

Troubleshooting

  • The Lock button is greyed out: the step is not complete; read the text to its left (e.g. “Entered 26/28 main teeth”). A record without a saved ID in step 1 cannot be locked either.
  • “Already has a record”: the sequence number is taken; click Next number.
  • An error after locking: click Unlock (give reason), correct, save, lock again. Do not change the clinical exam after seeing photos or AI results.
  • The Save button is greyed out: you are viewing the example record; click + New record.
  • Photos will not upload: the user has not been given edit permission; the owner grants it under Share.
  • Two people open the same record: each step is saved separately, so the examiner and the readers do not overwrite each other; two people should not edit the same step at the same time.

Records and data export

Each record has 6 parts; each part is saved separately, so several people can enter data at the same time without overwriting each other.

A .json file with every part and photo, to reopen later or move to another computer.
